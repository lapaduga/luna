# День 13+. Правки по отчёту партнёра (раунд 1)

Проект «Луна» — пилот «взломай LLM-приложение». Это отчёт об устранении
5 находок из атаки партнёра на `lapaduga/luna` (ветка main).

Дата: 2026-08-11.

---

## Что нашёл партнёр

1. **shy** — секрет с soft hyphen (U+00AD) между символами: 200 OK, не ловится.
2. **homoglyph** — `AKIA → АКIА` (кириллические буквы): 200 OK, не ловится.
3. **fullwidth** — `AKIA → ＡＫＩＡ` (full-width Unicode): 200 OK, не ловится.
4. **base64x2** — ключ закодирован base64 дважды: 200 OK; на выходе только
   `warn`, но маскировка не срабатывала (тип `BASE64` не участвовал в масках).
5. **перефразы** — 3 из 5 семантически тех же атак проходили `classifyRisk`
   с `risk: none`, и LLM-классификатор не вызывался (он срабатывает только
   на `medium`, а тут `none`).

Причины (по коду): `\w`/`\b` в JS — только ASCII; нормализации confusables
не было; `scanBase64` декодировал один уровень; `maskSecretTypes` не знал про
`BASE64`; эвристики — фиксированные формулировки.

## Что изменено в `guards.js`

| Правка | Суть |
|---|---|
| `INVISIBLE_RE` | расширен soft hyphen (U+00AD), bidi и формат-символами (`sanitizeText` режет их) |
| `normalizeForDetection()` | вырезает невидимые, сводит fullwidth→ASCII и кириллические homoglyphs→латиницу; возвращает карту позиций `map` |
| `detectCore` / `detectSecrets` | детекция идёт по нормализованному тексту |
| `base64Blobs()` + `scanBase64` | рекурсивный декод до глубины 3 — ловит base64x2/base64x3 |
| `maskSecretTypes()` | маскирует по нормализованному тексту с обратной картой в оригинал; добавлены `REDACTED_BASE64` / `REDACTED_BASE64_SECRET`; перекрытия склеиваются |
| `findProblemIndices()` | секреты ищутся в нормализованном тексте, индексы возвращаются в координатах оригинала (стрим режется до обфусцированного секрета) |
| `INJECTION_RULES` | +3 правила для перефразов: `extraction_quote`, `extraction_debug`, `instruction_supersede` |
| `classifyRisk()` | возвращает `review: true` для текстов с сигнальными словами, когда эвристики дали `none` |

Важная деталь правки: в JS `\w` и `\b` работают только с ASCII. Начальная версия
правил использовала `правил\w+` — не матчило кириллицу. Исправлено на `\p{L}`.

## Что изменено в `server.js`

Добавлена ветка для `risk.risk === 'none' && risk.review`: текст с сигнальными
словами (системный промпт, инструкции, правила и т.п.), который эвристики не
пометили, при включённом `GUARD_LLM` отправляется в LLM-классификатор; при
вердикте BLOCK — 403 (`blocked_injection_llm`). В лог пишется `input_review`.

## Проверка

### Юнит-тесты (`tests/guards.test.js`, 31 шт., все зелёные)

Новые кейсы:
- soft hyphen: ключ `A̸K̸I̸A̸…` ловится как `AWS_ACCESS_KEY`;
- fullwidth: `ＡＫＩＡ…` ловится;
- homoglyph: `АКIА…` ловится (и прежний «пробел» `sк-` закрыт);
- base64x2: `BASE64_SECRET` hard;
- `maskSecretTypes` маскирует homoglyph-email и base64-блоб;
- `findProblemIndices` находит обфусцированный ключ в координатах оригинала;
- 3 перефраза → `high`;
- `review`-флаг ставится на спорных текстах, чистые — нет.

## Ограничения (честно)

- Правила перефразов — по-прежнему regex: другие формулировки могут пройти.
  Полноценную защиту от перефраза даёт `GUARD_LLM=1` (теперь он вызывается и
  для `none`+`review`). В текущем конфиге `GUARD_LLM=0` — эвристики и `review`
  работают, но LLM-перепроверка выключена.
- Нормализация не решает проблему «новых» homoglyphs — таблица `CYRILLIC_TO_LATIN`
  ограничена визуально похожими буквами. Прочие Unicode-confusables
  (например, греческие/латинские) можно добавлять в ту же таблицу.
